> **Claude Code 注**:本 skill 的"自动触发"依赖 Claude Code hook(在 `.claude/settings.json` 中配置 `Stop` 或 `PostToolUse` hook)或由用户显式调用。未配置 hook 时,需用户手动触发(输入"记录日志"或 `/log`)。

## What I do

自动将完成的工作记录追加到今天的日志文件中，并同步提交到 Git 仓库。

- 每次完成一个任务后，读取今天的日志文件（`logs/daily/YYYY-MM-DD.md`）
- 如果文件不存在，从模板 `logs/templates/daily-template.md` 创建
- 将工作摘要追加到「今日活动」部分
- 自动执行 Git 提交，将日志变更同步到版本控制
- 覆盖范围：代码开发、文档编写、问题分析、工具使用、SOP 执行等

## When to use me

在以下场景自动触发：

1. 你刚完成了一项用户交代的任务（编写代码、创建文档、执行 SOP 等）
2. 用户明确要求记录日志
3. 用户输入 `/log` 命令

**Git 提交策略**：
- 仅在 `echo-dev` 分支自动提交
- 其他分支需要手动确认
- 避免在主分支（`master`）自动提交

## How to log

### 日志文件路径

```
logs/daily/YYYY-MM-DD.md
```

其中 `YYYY-MM-DD` 是今天的日期。

### 模板位置

```
logs/templates/daily-template.md
```

### 追加格式

每次记录追加到「今日活动」表格中，格式如下：

```markdown
| HH:MM | 模块 | 活动摘要 | 状态 |
```

- **HH:MM**：当前时间（24h 格式）
- **模块**：任务所属模块（如 SOP 系统、工具开发、文档、Desense 分析等）
- **活动摘要**：一句话描述完成的工作，附带关键结果
- **状态**：✅ 完成

### 示例追加

```
| 14:30 | SOP 系统 | 创建 W24-02 (Camera MIPI → WiFi 2.4G) SOP | ✅ 完成 |
| 15:00 | 工具开发 | 优化 harmonic_calc.py 增加批量计算功能 | ✅ 完成 |
```

### 详细记录

如果任务较复杂（如 SOP 编写、问题分析），在「详细记录」部分追加条目：

```markdown
### [HH:MM] 活动标题

- **模块**：模块名称
- **任务**：具体做了什么
- **关键产出**：创建/修改了哪些文件
- **备注**：需要注意的事项
```

### 规则

1. **只追加，不覆盖**：已有内容不修改，只在末尾追加
2. **一条任务一条记录**：不合并多个任务
3. **简洁摘要**：每条记录不超过 2 行
4. **文件路径要带**：涉及文件操作时记录文件路径

## Git 集成

### 自动提交流程

每次日志追加完成后，自动执行以下 Git 操作：

1. **检查当前分支**：
   ```bash
   git branch --show-current
   ```

2. **仅 `echo-dev` 分支自动提交**：
   - 如果在 `echo-dev` 分支，自动执行提交
   - 如果在其他分支，建议用户手动提交
   - 主分支（`master`）禁止自动提交

3. **Git 操作步骤**：
   ```bash
   # 添加日志文件
   git add logs/daily/YYYY-MM-DD.md
   
   # 生成提交消息
   git commit -m "docs: 更新日志 - [时间] [模块] [摘要]"
   ```

### 提交消息格式

```
docs: 更新日志 - [HH:MM] [模块] [活动摘要]
```

**示例**：
- `docs: 更新日志 - 14:30 Desense分析 完成WiFi2.4G排查`
- `docs: 更新日志 - 15:00 工具开发 优化谐波计算脚本`

### 分支管理策略

| 分支 | 自动提交 | 说明 |
|------|----------|------|
| `echo-dev` | ✅ 自动 | 开发分支，可自动提交 |
| `master` | ❌ 手动 | 主分支，需人工审核 |
| 其他分支 | 🔄 建议 | 建议手动提交或合并到 `echo-dev` |

### 手动触发命令

除了自动触发，还支持手动命令：

- **`/log`**：仅记录日志，不提交 Git
- **`/log-git`**：记录日志并立即提交 Git
- **`/git-log`**：仅提交当前日志变更到 Git

### 统计更新

每次 Git 提交后，自动更新日志文件中的统计信息：

```markdown
- **提交次数**：X（自动增量）
- **新建文件**：Y
- **修改文件**：Z
```

### 冲突处理

如果 Git 提交失败（如冲突）：
1. 记录错误信息到日志
2. 建议用户手动解决冲突
3. 不中断后续操作
