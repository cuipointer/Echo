## 1. 优先级定义

### 场景优先级等级

| 优先级 | 场景 | 限值要求 | 排查顺序 | 原因 |
|:---|:---|:---|:---|:---|
| **P0** | **Normal** | ≤ 1dB | **第一** | 基准线，影响所有场景 |
| **P1** | **LCD** | ≤ 3dB | 第二 | 常亮场景，用户感知强 |
| **P2** | **Camera** | ≤ 4dB | 第三 | 高频使用场景 |
| **P3** | **VIB / Charger** | ≤ 3dB | 第四 | 特定场景，可规避 |
| **P4** | **USB / 下载** | ≤ 5dB | 第五 | 数据传输场景 |

### 优先级说明

#### P0 - Normal（最高优先级）
- **定义**：灭屏+所有功能关闭状态
- **重要性**：所有场景的基准线
- **排查要求**：必须先达标才能排查其他场景
- **限值**：≤1dB（研发内部要求）

#### P1 - LCD（高优先级）
- **定义**：亮屏常亮状态
- **重要性**：用户最常接触的场景
- **排查要求**：Normal达标后优先排查
- **限值**：≤3dB

#### P2 - Camera（中优先级）
- **定义**：相机预览/录像状态
- **重要性**：高频使用功能
- **排查要求**：Normal和LCD达标后排查
- **限值**：≤4dB

#### P3 - VIB/Charger（中优先级）
- **定义**：振动/充电状态
- **重要性**：特定功能场景
- **排查要求**：基础场景达标后排查
- **限值**：≤3dB

#### P4 - USB/下载（低优先级）
- **定义**：数据传输/高速下载状态
- **重要性**：性能场景
- **排查要求**：最后排查
- **限值**：≤5dB

## 2. 排查顺序铁律

### 标准排查流程

```
1. 先查 Normal（≤1dB 是前提）
   ↓
2. 再查 LCD（≤3dB）
   ↓  
3. 然后查 Camera（≤4dB）
   ↓
4. 最后查 VIB/Charger/USB（按需）
```

### 排查中断规则

- **如果Normal超标**：停止所有场景排查，先解决Normal
- **如果LCD超标**：停止Camera及后续排查，先解决LCD
- **逐级排查**：上一级达标后才能进入下一级

### 场景干扰计算

```
场景总干扰 = Normal Desense + 场景额外干扰

排查目标：使场景额外干扰 ≤ 场景限值
```

## 3. Echo 行为规范

### 用户交互流程

当用户报告某场景 Desense 时，Echo 必须：

1. **第一步：询问Normal状态**
   ```
   "Normal Desense测试过了吗？值是多少？"
   ```

2. **第二步：判断优先级**
   - 如果用户未测试Normal → 建议先测试Normal
   - 如果Normal > 1dB → 引导进入Normal排查
   - 如果Normal ≤ 1dB → 进入具体场景排查

3. **第三步：计算额外干扰**
   ```
   "Normal达标，当前场景的额外干扰为 X dB"
   ```

### 错误处理

#### 常见错误模式

| 错误模式 | 正确处理 |
|:---|:---|
| 跳过Normal直接查场景 | 提醒用户先测试Normal |
| Normal超标但继续场景排查 | 引导先解决Normal |
| 未计算额外干扰 | 自动计算并告知用户 |

#### 用户教育

```
"Normal是所有场景的基准线，必须先达标。
当前场景总干扰Y dB，Normal贡献X dB，
实际场景额外干扰为(Y-X) dB。"
```

## 4. 技术依据

### 系统级影响分析

#### Normal的影响范围
- **天线TIS**：直接影响整机天线性能
- **所有场景**：Normal不达标会放大所有场景干扰
- **设计验证**：代表系统本底噪声水平

#### 场景叠加特性
- **LCD**：在Normal基础上叠加显示相关噪声
- **Camera**：在Normal基础上叠加摄录相关噪声
- **其他场景**：各自的功能噪声叠加

### 用户体验考量

#### 使用频率
- **Normal**：始终存在（待机状态）
- **LCD**：最高频使用场景
- **Camera**：次高频使用场景
- **其他**：特定功能场景

#### 感知强度
- **Normal**：基础信号质量
- **LCD**：直接影响日常使用
- **Camera**：影响拍照体验
- **其他**：特定功能体验

## 5. 实施指南

### 测试流程规范

#### 标准测试顺序
1. **传导测试**：建立基准
2. **Normal测试**：灭屏+全关功能
3. **场景测试**：按优先级顺序

#### 数据记录要求
```markdown
## Desense测试记录

### Normal基准
- 传导灵敏度：各频段基准值
- Normal Desense：各频段恶化值

### 场景干扰
- 场景总干扰：实测值
- 额外干扰 = 总干扰 - Normal
- 是否达标：对比场景限值
```

### 问题定位流程

#### 第一步：系统级问题
- 检查Normal是否达标
- 排查电源、时钟、屏蔽等系统问题

#### 第二步：功能级问题
- Normal达标后排查具体场景
- 定位功能模块相关干扰

#### 第三步：优化级问题
- 微调参数和配置
- 实现最优性能
