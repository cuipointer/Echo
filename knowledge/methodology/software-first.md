# 软件优先原则

## 核心理念

**拆机前验证所有软件措施，拆机后状态改变，不可逆。**

## 为什么软件优先？

1. **可逆性**：软件修改可以随时回滚，硬件修改往往不可逆
2. **成本低**：软件修改无需物料成本和生产周期
3. **效率高**：软件验证可以快速迭代，硬件验证需要反复拆装
4. **风险小**：避免因误判导致不必要的硬件改动

## 软件措施清单

### 1. 频率调整
- **展频 (SSC)**：降低基频峰值功率
- **时钟调整**：改变干扰源频率，避开受扰体频段
- **占空比调整**：优化 PWM 信号波形

### 2. 功能开关
- **关断干扰源**：关闭不必要的模块
- **降低功耗**：降低干扰源工作强度
- **模式切换**：切换到低干扰模式

### 3. 调度策略
- **错峰工作**：避免干扰源与受扰体同时工作
- **优先级调整**：调整任务调度优先级
- **动态调整**：根据场景动态调整参数

### 4. 滤波算法
- **数字滤波**：在基带处理中滤除干扰
- **增益控制**：调整接收增益
- **算法优化**：优化信号处理算法

## 软件排查流程

### 第一步：场景复现
1. 确认受扰频段
2. 确认测试场景（亮屏、充电、摄像等）
3. 记录干扰现象（灵敏度恶化程度）

### 第二步：干扰源确认
1. 使用决策树定位可疑干扰源
2. 通过开关测试确认干扰源
3. 记录干扰源工作参数

### 第三步：频率验证
1. 测量干扰源基频
2. 计算谐波命中情况
3. 确认频率重叠关系

### 第四步：软件规避尝试
1. 尝试展频时钟
2. 尝试频率调整
3. 尝试功能开关
4. 记录改善效果

## 硬件措施触发条件

仅在以下情况考虑硬件措施：

1. **软件无效**：所有软件措施均无改善
2. **设计缺陷**：确认为设计阶段未考虑的干扰
3. **合规要求**：需要满足特定认证要求
4. **量产需求**：需要在量产前完成整改

## 注意事项

1. **记录完整**：每次软件修改需记录参数和效果
2. **对比测试**：修改前后需对比测试，量化改善效果
3. **回归测试**：验证修改不影响其他功能
4. **文档更新**：更新设计文档和测试报告
