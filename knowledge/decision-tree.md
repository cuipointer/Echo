## 决策树结构

决策树用于从现象收敛到"干扰源类别"，是标准化排查流程的第一层。

**输入**：受扰频段 + 测试场景  
**输出**：可疑干扰源  
**下一步**：查询矩阵表获取SOP编号

## Normal 优先逻辑（新增入口）

```
任何 Desense 问题入口
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  ⚠️ 第一步：确认 Normal Desense 是否达标（≤1dB）             │
│                                                             │
│  如果 Normal > 1dB → 先走 Normal 排查流程                    │
│  如果 Normal ≤ 1dB → 再排查具体场景                          │
└─────────────────────────────────────────────────────────────┘
    │
    ├── Normal 超标 ─────────────────────────────────────────┐
    │                                                        │
    │   Normal Desense 排查                                   │
    │       │                                                │
    │       ├── 传导正常？ → 否 → 解决传导                    │
    │       ├── 大小功率一致？ → 否 → 查非线性/匹配            │
    │       ├── 查交调源：LCD/Camera/SPK/马达/光感...         │
    │       ├── 查电源/时钟：PMIC/OSC                         │
    │       └── 查屏蔽/接地                                   │
    │                                                        │
    │   参考SOP：NORMAL系列（NORMAL-01到NORMAL-08）            │
    │                                                        │
    └────────────────────────────────────────────────────────┘
    │
    └── Normal 达标 ─────────────────────────────────────────┐
                                                             │
         确认具体场景（LCD / Camera / VIB / Charger ...）      │
             │                                               │
             └── 走对应场景的决策树分支                         │
                                                             │
└────────────────────────────────────────────────────────────┘
```

### Normal 排查要点
1. **优先级最高**：Normal 是基准线，必须先达标
2. **传导确认**：先排除传导问题，再排查辐射问题
3. **系统性排查**：涉及电源、时钟、屏蔽等系统级问题
4. **场景干扰计算**：场景额外干扰 = 总干扰 - Normal Desense

## Camera 专用分支

```
Camera 预览/录像 Desense
    │
    ├── 第一步：干扰源初步定位
    │   ├── 关闭 Camera → 干扰消失？
    │   │   ├── 是 → 确认为 Camera 相关
    │   │   └── 否 → Camera 非主因，查其他源
    │   │
    │   ├── 切换分辨率/帧率 → 干扰频率变化？
    │   │   ├── 是 → MIPI 时钟/数据相关（优先级最高）
    │   │   │       └── 计算 MIPI Clock，尝试改频/SSC
    │   │   └── 否 → MCLK 或固定时钟相关
    │   │           └── 查 MCLK 滤波和频率规划
    │   │
    │   ├── 前后摄表现差异大？
    │   │   ├── 是 → 特定模组/FPC 布局问题
    │   │   │       └── 定位到具体模组进行针对性整改
    │   │   └── 否 → 系统级问题（CPU/电源/结构）
    │   │
    │   └── 对焦/闪光灯时加重？
    │       ├── 对焦加重 → VCM 驱动噪声
    │       │       └── 优化 VCM 驱动时序和滤波
    │       └── 闪光灯加重 → Flash LED 大电流开关
    │               └── Flash 电源滤波和时序控制
    │
    ├── 第二步：频率分析
    │   ├── 谐波命中计算
    │   │   ├── MIPI Clock = Frame × H × V × Pixel / Lane / 2
    │   │   ├── 谐波阶数 = 受扰频率 / 基频
    │   │   └── 关注 2-200 次谐波风险
    │   │
    │   ├── 个别频段/信道干扰差异？
    │   │   ├── 是 → 时钟谐波命中，重点改频/SSC
    │   │   └── 否 → 宽带噪声，查电源 SSN/屏蔽
    │   │
    │   └── 频谱特征分析
    │       ├── 离散谱线 → 时钟谐波
    │       ├── 连续宽带 → 电源 SSN/数据噪声
    │       └── 脉冲干扰 → 开关电路（VCM/Flash）
    │
    ├── 参考SOP：对应频段的Camera SOP（GL1-02/W24-02等）
    └── 验证方法：分辨率切换 + 前后摄对比 + 功能开关测试
```

### Camera 排查要点
1. **信号流向关键认知**：Camera MIPI 方向与 Display 相反（Camera → CPU）
2. **主要干扰源优先级**：MIPI CSI Clock > MCLK > AVDD SSN > VCM/Flash
3. **频率计算核心**：MIPI Clock = Frame × H × V × Pixel / Lane / 2
4. **内部限值差异**：≤ 4dB（比亮屏 3dB 宽松）
5. **软件优先原则**：先尝试 SSC/改频/降帧率，再考虑硬件整改
6. **排查优先级**：分辨率影响测试 > 前后摄对比 > 功能开关测试

### WiFi 2.4G 排查要点
1. **优先级**：亮屏 > 下载 > 充电 > 相机 > 通话
2. **谐波关注**：MIPI基频的30次谐波（~2400MHz）
3. **信道差异**：检查各信道（1/6/11）恶化程度

## 决策树使用方法

### 第一步：Normal状态确认（新增）
1. **测试Normal Desense**：灭屏+所有功能关闭状态下测试
2. **判断达标情况**：
   - Normal ≤ 1dB → 进入具体场景排查
   - Normal > 1dB → 先解决Normal问题
3. **记录Normal值**：作为场景干扰计算的基准

### 第二步：问题输入
1. 确认受扰频段（WiFi/GNSS/LTE）
2. 确认测试场景（亮屏/充电/USB等）
3. 记录场景总干扰程度（dB）

### 第三步：选择分支
1. 根据Normal状态选择路径
2. 根据受扰频段选择对应决策树分支
3. 根据测试场景选择子分支
4. 获取可疑干扰源列表

### 第三步：验证干扰源
1. **开关测试**：
   ```bash
   # LCD测试
   adb shell input keyevent 26  # 灭屏
   
   # 相机测试
   # 关闭相机APP
   
   # USB测试
   # 拔出USB设备
   ```

2. **频率验证**：
   - 测量干扰源实际基频
   - 使用频谱仪观察受扰频段
   - 计算谐波关系

3. **记录确认**：
   - 干扰源模块
   - 干扰频率
   - 恶化程度

### 第四步：进入矩阵层
1. 确认干扰源和受扰体组合
2. 查询矩阵表获取SOP编号
3. 执行标准化排查SOP

## 谐波计算指导

### 常见干扰源基频
| 干扰源 | 基频范围 | 典型值 |
|--------|----------|--------|
| LCD MIPI | 60-120MHz | 80MHz |
| Camera MIPI | 200-800MHz | 400MHz |
| Camera MCLK | 24-27MHz | 24MHz |
| DDR | 200-933MHz | 400MHz |
| PMIC Buck | 1-4MHz | 2MHz |
| VIB PWM | 20-50kHz | 30kHz |
| USB 3.0 | 2.5GHz/5GHz | 2.5GHz |

### 谐波计算公式
```
干扰频率 = 基频 × N（N为谐波次数）
```

### 命中判断
- 计算谐波是否落入受扰体频段
- 关注±5%的频率容差
- 考虑展频时钟的影响

## 注意事项

### 1. 多干扰源场景
- 实际场景可能存在多个干扰源
- 需逐一排查，避免遗漏
- 记录每个干扰源的贡献

### 2. 谐波干扰
- 决策树基于基频分析
- 需考虑谐波命中
- 高次谐波能量较弱，但仍可能造成干扰

### 3. 场景组合
- 复杂场景需组合多个分支判断
- 例如：亮屏+充电+USB同时存在
- 分别排查各场景干扰

### 4. 验证确认
- 所有可疑源需通过测试验证
- 记录完整的验证过程
- 确保结论准确可靠

- 大小功率差异 → 非线性器件/匹配

- 亮屏 → LCD MIPI

- 充电 → Charger
