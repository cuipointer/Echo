# SOP-GL1-03:DDR → GNSS L1

**版本**:v0.9.0
**日期**:2026-05-06
**状态**:**方法论版(待现场复测)** — 从 placeholder v0.1 升级,基于 EMC 2024 C.3 案例反哺 + W24-03 结构参照 + GL1-01 GPS 特别要求参照,**未经现场实测验证**

> **复测提醒**:GPS L1 敏感度 -140 ~ -150 dBm,任何 dB 恶化都严重,本 SOP 阈值比 WiFi/LTE 严;现场必须关注 PMIC / DDR 屏蔽罩设计缺陷。

---

## 一、组合信息

### 干扰源
- **模块**:DDR(Double Data Rate SDRAM,含 DDR Controller + DDR PHY)
- **代码**:DD
- **分类**:存储
- **噪声来源**:内存时钟、数据线开关噪声、DDR PHY 训练时的突发噪声、DDR VDD 供电纹波
- **基频范围**:200-933 MHz(典型 LPDDR5 / LPDDR4X / LPDDR4)
- **典型干扰**:**宽带底噪在 1.5-1.7 GHz 区间有持续能量分布**(非单点谐波主导);特定 DDR 频率 2-8 次谐波可能命中 L1

### 受扰体
- **频段**:**GNSS L1**
- **代码**:GL1
- **频率范围**:1561-1606 MHz(含 GPS L1 1575.42 / BDS B1 1561.098 / GLONASS G1 1598-1606 / Galileo E1 1575.42)
- **敏感度要求**:**-140 ~ -150 dBm**
- **GPS 特别要求**:**3 dB 恶化即视为严重问题**,需立即立项排查(详见第二节 GPS 敏感性专节)

### 耦合路径
- **主要类型**:**辐射耦合**(屏蔽罩设计开窗 / PCB 层间 / 下天线靠近 DDR/PMIC 区域)
- **次要类型**:**传导耦合**(DDR 供电平面纹波 → PMIC → GPS LNA 电源)
- **机制**:
  - 辐射路径 A:DDR 宽带底噪 → DDR 屏蔽罩泄露 → 空间 → GPS 天线(上/下天线)
  - 辐射路径 B:**DDR 噪声 → BOT 面 PMIC 屏蔽罩顶部开窗 → PCB 另一面 → GPS 天线**(C.3 O11U 案例典型路径)
  - 传导路径:DDR VDD 纹波 → 电源平面 → GPS LNA / RF 前端电源 → 噪底抬升
  - 结构性路径:BOT 面 DDR / PMIC 与 GPS 天线近距离,中间仅有 PCB 层间隔离,层数不足时直耦

### 矩阵元信息
- **优先级**:**P0**(GPS 特别要求决定了优先级高于 WiFi/LTE 同源同路径问题)
- **典型恶化量**:2-5 dB(C.3 案例中 3 dB 即被判为严重 / 立项)
- **快速诊断提示**:**在弱信号环境复测**(非明场信号余量环境,否则 3 dB 会被余量淹没)+ 停止 DDR 负载对照

## 二、理论预判

### 谐波命中计算

DDR 基频 200-933 MHz,2-8 次谐波可能命中 GNSS L1(1561-1606 MHz):

| DDR 基频 | 谐波次数 | 命中频点 | 是否命中 L1(1561-1606) |
|---|:---:|---|:---:|
| 200 MHz | 8 | 1600 MHz | ✓ 中段 |
| 266 MHz | 6 | 1596 MHz | ✓ 中段 |
| 400 MHz | 4 | 1600 MHz | ✓ 中段 |
| 533 MHz | 3 | 1599 MHz | ✓ 中段 |
| 800 MHz | 2 | 1600 MHz | ✓ 中段 |
| 933 MHz | 1.7 | 1586 MHz | ✓(非整数,来自宽带底噪而非谐波) |

**结论**:主流 DDR 频率都存在 2-8 次谐波命中 L1 的可能;**但 DDR Desense GPS 更常见的形态是宽带底噪在 L1 附近抬升**,而非单一谐波尖峰 —— 这与 WiFi 2.4G 被 DDR 干扰时常见的"明确谐波尖峰"形态不同,诊断时需要注意频谱测试方法的差异(详见第三节步骤 3)。

### GPS 敏感性专节(为什么 3 dB = 严重)

这是 GL1 系列 SOP 的**核心专节**,决定了本 SOP 的阈值与 WiFi/LTE SOP 不同。

**1. GPS L1 接收机敏感度量级**:
- 冷启动捕获门限:约 **-148 dBm**(典型 -140 ~ -150 dBm)
- 热跟踪门限:约 **-160 dBm**
- WiFi 2.4G 敏感度对照:约 -82 ~ -90 dBm(比 GPS 低 **60-70 dB**)
- LTE 低频敏感度对照:约 -94 ~ -102 dBm(比 GPS 低 **40-50 dB**)

**2. 3 dB 恶化的实际影响**:
- **定位成功率**:在开阔天空(信号余量 > 10 dB)可能无感知;但在**室内 / 地下车库 / 高层峡谷 / 树荫下**,卫星信号可能本身就接近门限,3 dB 恶化直接导致该场景下**定位失败**
- **TTFF(首次定位时间)**:恶化后可用卫星数减少,冷启动 TTFF 从典型 30 秒拉长到 **60-120 秒或失败**
- **定位精度**:参与解算的卫星几何(DOP)恶化,横向精度从米级恶化到 10 米级
- **用户感知**:导航场景下定位漂移、无法启动、重新定位慢 —— 是非常明显的体验事故

**3. 为什么 WiFi / LTE 能容忍 3 dB 而 GPS 不能**:
- WiFi / LTE 是**双向链路**,有功率控制 / 重传 / MCS 降阶等补偿机制,3 dB 恶化可通过业务层吸收
- GPS 是**单向接收**,卫星发射功率固定,没有链路层补偿 —— 所有恶化直接体现为可用性损失
- GPS 信号本身就靠**扩频增益(~43 dB)** 才能解出,余量极小

**4. 本 SOP 的阈值口径(与 WiFi/LTE SOP 对照)**:

| 等级 | W24-03 阈值 | GL1-03 阈值(严) |
|---|---|---|
| 无需处理 | < 1 dB | < 0.5 dB |
| 关注 | 1-3 dB | 0.5-1.5 dB |
| 立项 | 3-5 dB | **≥ 1.5 dB** |
| 严重 / 必改版 | > 8 dB | **≥ 3 dB** |

### 设计审查必查项(GPS 专用)

1. **屏蔽罩开窗设计 —— 必须标注(C.3 核心启示)**:
   - **凡是为工艺便利(打件 / 测试点 / 散热 / 标签)而在屏蔽罩上开的窗,都必须在 RF 协同 review 时显式列出**
   - 重点区域:CPU / DDR / PMIC 屏蔽罩,特别是 **BOT 面 PMIC 屏蔽罩顶部**(C.3 案例证实是隐蔽泄露路径)
   - 正常装配 ≠ 设计合规:装配工艺合规的开窗若对 GPS 敏感,仍必须封闭
2. **PCB BOT 层 PMIC / DDR 布局**:BOT 面是否靠近 GPS 天线馈电 / 主地平面缺口
3. **GPS 天线物理距离**:GPS 天线与 DDR / PMIC / CPU 屏蔽罩的距离,最小净空 / 金属件距离
4. **屏蔽罩接地完整性**:屏蔽罩与主板 / 中框的接地点密度,是否有大间距地
5. **GPS LNA 电源滤波**:GPS LNA VCC 与 DDR 供电是否共域 / 滤波网络是否独立
6. **DDR 走线屏蔽**:DDR 信号线周围包地过孔密度,是否穿过 GPS 敏感区域
7. **中框槽天线设计**:若为槽天线,槽口是否正对 BOT 面噪声源

**参考案例**:
- [O11U-GL1-shield-aperture.md](../../cases/O11U-GL1-shield-aperture.md) — C.3 原型,42 天设计级改版,PMIC 屏蔽罩顶部开窗取消 + 积水铜箔
- EMC 2024 C.3(多源叠加:DDR + PMIC + SHIELD_LEAK 三条矩阵同时命中)

## 三、软件排查步骤

### 步骤 1:场景复现(**GPS 必须在弱信号环境测**)

**目标**:确认 DDR 场景下 GPS L1 Desense 可复现,且恶化量不被信号余量淹没

**GPS 场景的特别要求**:
- **必须在弱信号环境测**:信号屏蔽箱模拟低电平信号(-130 ~ -145 dBm),或实验室暗室 + 信号源
- **如果仅在明场(开阔天空)测,3 dB 恶化会被 10+ dB 信号余量淹没 → 漏检**
- 测试项:**TTFF(冷启动 / 热启动)** + **跟踪灵敏度** + **捕获灵敏度** + **C/N0(载噪比)**

**操作**:
1. 暗室 / 屏蔽箱内,GPS 信号源设置 -145 dBm(接近冷启动门限)
2. 空载(CPU idle,DDR 低频)测量 TTFF + C/N0 → 基线
3. 启动 DDR 压测 / 下载 / 内存拷贝,使 DDR 达到高带宽和高频(如 LPDDR5 6400)
4. 压测中测量同样的 TTFF + C/N0
5. 差值 = DDR 场景 Desense(dB / TTFF 延长秒数)

**预期结果**:DDR 压测时 C/N0 下降 2-5 dB,TTFF 延长或失败

### 步骤 2:干扰源确认

**目标**:确认 DDR 为主要干扰源

**操作**:
1. **停止下载 / 减负载**:C/N0 是否恢复?
   - 是 → DDR 负载相关
   - 否 → 转 Normal 或 PMIC / CPU 相关排查(可能是 GL1-04 或 NORMAL-07)
2. **切换 DDR 频率**(DVFS 降频到 LPDDR 低档位):观察 C/N0 改善
3. **跑 Camera / 下载 / 纯内存压测**:对比哪种场景 C/N0 最差
4. **观察时域**:压测瞬间 vs 稳态的 C/N0 变化

**预期结果**:确认 DDR 负载与 Desense 正相关。**若停止 DDR 后仍有恶化,立即触发步骤 2.6 多源叠加排查(C.3 典型场景)**

### 步骤 2.5:子功能逐项排查(零成本验证)

**目标**:排除其他子功能干扰,分离 DDR 单独贡献

**操作**(按零成本顺序):
1. 关闭屏幕(排除屏 MIPI → GL1-01)
2. 断开 USB(排除 USB 3.0 干扰)
3. 只跑纯内存压测(不跑网络下载,排除 WiFi / 蜂窝自身发射影响)
4. 关闭摄像头(排除 Camera MIPI)
5. 关闭 NFC / 蓝牙(排除共存干扰)

**预期结果**:隔离出 DDR 单独贡献的 C/N0 下降量

### 步骤 2.6:多源叠加排查(**C.3 案例核心场景,本 SOP 典型必查**)

**触发条件**:
- 步骤 2.5 排除其他功能后仍有残余 Desense
- 停止 DDR 后 Desense 未完全恢复
- 或:常规 DDR 整改措施改善有限,但现象明显与 BOT 面 / 屏蔽罩相关

**说明**:C.3 O11U 案例即多源叠加典型 —— `DDR → GL1 = GL1-03` + `PMIC → GL1 = GL1-04` + `SHIELD_LEAK → NORMAL = NORMAL-07` 三条矩阵映射**同时命中**。GPS L1 区域噪声通常不是单一源,而是 DDR + PMIC 宽带底噪共同抬升,加上屏蔽罩开窗放大辐射。

**操作**:按 [`_template.md` 步骤 2.6](../_template.md) 多源叠加排查法枚举候选源:
- H1:DDR 时钟 / 数据噪声(本 SOP 主假设)
- H2:**PMIC 开关噪声 → 跨引用 [GL1-04](GL1-04.md)**
- H3:BOT 面屏蔽罩设计开窗(C.3 根因)
- H4:GPS LNA 电源纹波
- H5:CPU 屏蔽罩泄露(压测时 CPU 高负载)

**分离验证方法**:
1. 铜箔临时封顶 BOT 面 PMIC 屏蔽罩 → 若 Desense 改善 ≥ 1 dB,H3 确认
2. 单独降 DDR 频率(不改 PMIC 负载)→ 分离 H1 贡献
3. 改变 PMIC 开关频率(若支持)→ 分离 H2 贡献

### 步骤 3:频率验证(**L1 附近需要低噪放大 + 频谱仪**)

**目标**:验证 L1 频段噪底抬升来源

**GPS 特别要求**:
- GPS 信号 -140 dBm 级,普通频谱仪底噪(-100 ~ -120 dBm)高于 GPS 信号,**必须前端加低噪放大器(LNA,Gain ≥ 30 dB,NF ≤ 1 dB)**
- 扫频范围:1555-1610 MHz,RBW 100 kHz ~ 1 MHz,VBW 10 kHz
- 观察:**寻找尖峰 spur(单频谐波)+ 宽带底噪抬升量**(两种形态并存)

**操作**:
1. 读取当前 DDR 频率(通过系统 log 或 PMIC / DDR command)
2. 计算该频率 2-8 次谐波,找出落在 L1 内的次数
3. 加 LNA 接频谱仪,对比空载 vs DDR 压测下 L1 频段的谱线
4. 改 DDR 频率(DVFS 档位)看干扰频点 / 底噪是否移动

**预期结果**:
- 若有明显 spur → 窄带谐波命中(与谐波计算对照)
- 若整段底噪抬升 → 宽带泄露(本 SOP 更常见形态,指向屏蔽罩 / 电源路径)

### 步骤 4:软件规避尝试(**GPS 场景软件规避效果有限**)

**目标**:软件优先措施,但需认识到 GPS 场景的局限性

**GPS 特别要求**:
- **GPS 场景不可避让**:用户启动导航时系统无法降低 DDR 频率(性能 / 实时性要求),不像 WiFi 下载可以业务层调度
- 调度避让仅在"已知定位中"可以尝试,但效果有限

**操作**:
1. **DDR 频率调整**:DVFS 策略避开命中 L1 的频率(代价是性能)
2. **DDR Refresh 策略优化**:降低 Refresh 频率(较小改善)
3. **定位期间调度降 DDR**:定位 Active 时限制 DDR 最高档位(需系统 / 框架支持,用户感知为定位中卡顿)
4. **GPS 信号处理参数**:数字滤波器 NV 调参(参考 A.1 案例思路,效果有限)

**预期结果**:软件措施通常改善 0.5-2 dB,**对结构性 / 设计级泄露(如 C.3 的屏蔽罩开窗)无效 —— 必须进入硬件路径**

## 四、硬件排查步骤(**本 SOP 主路径**)

**触发条件**:软件改善 < 1.5 dB,或现场情况符合 C.3 多源叠加 / 设计级缺陷特征

### 步骤 1:近场定位(**重点扫 BOT 面 + GPS 天线附近**)

**目标**:找到最强辐射点,判定辐射 vs 传导 vs 结构性路径

**操作**:
1. **近场扫描**:
   - 重点区域:**BOT 面 PMIC / DDR 屏蔽罩周围**(C.3 根因位置)、CPU 屏蔽罩、GPS 天线馈电附近、B2B 连接器
   - 扫频范围 1561-1606 MHz,使用 H 场环探头(对辐射最敏感)
2. **临时屏蔽测试**:用铜箔临时封住可疑泄露点(特别是 BOT 面屏蔽罩顶部),看改善
3. **电源纹波测量**:测 DDR VDD / PMIC BUCK 在 L1 频段内的纹波
4. **天线拉距测试**:若条件允许,外接天线到远离 DDR / PMIC 的位置,看改善

**预期结果**:定位最强辐射点,识别路径类型

### 步骤 2:屏蔽罩密封检查(**必查顶部开窗,C.3 核心教训**)

**目标**:区分"装配级泄露"和"设计级开窗泄露"

**C.3 核心教训**:**正常装配不代表设计合规** —— 屏蔽罩可能在设计图纸上就有开窗(为打件 / 贴片 / 测试 / 标签工艺便利),装配合规但设计本身不合规,对 GPS 敏感度仍有严重影响。

**操作**:
1. **调出屏蔽罩设计图纸**:列出所有开窗 / 开孔的位置和尺寸
2. **标注开窗用途**:打件 / 测试 / 散热 / 标签 / 其他;**所有"工艺便利性开窗"重点标注**
3. **铜箔临时封闭每个开窗**:逐一验证,哪个开窗封闭后 C/N0 改善最大
4. **对比多台样机**:如果只有部分样机严重,可能是装配差异;如果所有样机都严重 → 设计级缺陷

**预期结果**:定位设计级开窗泄露点;若封闭后改善 ≥ 1.5 dB,判定为设计级缺陷,触发步骤 3

### 步骤 3:屏蔽罩改版(**设计级改版,C.3 最终方案**)

**目标**:彻底封闭设计级开窗

**操作**:
1. **屏蔽罩开窗取消**:与结构 / 工艺团队协同,评估取消开窗的工艺代价(打件 / 测试 / 标签 alternatives)
2. **积水铜箔方案**:若完全取消开窗不可行,采用"积水铜箔"方式覆盖开窗(C.3 最终方案)—— 铜箔与屏蔽罩电气连接,填补电气密封
3. **点胶 / 导电胶补强**:屏蔽罩焊点加强,减少装配间隙
4. **新增单点接地**:屏蔽罩与中框之间增加单点接地(参考 C.2 思路)

### 步骤 4:PCB 层叠 / 布局优化

**目标**:从根源隔离 DDR / PMIC 噪声到 GPS 的耦合

| 整改点 | 措施 | 预期改善(GPS 场景) |
|---|---|:---:|
| BOT 面屏蔽罩顶部开窗(C.3 类) | 取消开窗 / 积水铜箔 | **2-4 dB** |
| BOT 面 PMIC 屏蔽罩密封 | 全方位导电泡棉压紧,加强接地 | 1-3 dB |
| GPS LNA 电源滤波 | 独立 LDO / 加大去耦电容 + 串磁珠 | 1-2 dB |
| DDR 电源滤波 | VDD_MX / VDDQ 加大容值 | 0.5-1.5 dB |
| GPS 天线拉距 | 天线与 DDR / PMIC 区域拉开物理距离 | 1-3 dB(视原距离) |
| PCB 层叠优化 | GPS 天线馈线下方增加完整地平面层 | 1-2 dB |
| 中框接地 | 屏蔽罩与中框间接地点密度加大 | 1-2 dB |

**预期结果**:综合改善到 **≤ 1.5 dB**(GPS 内部限值)

### 案例 1:O11U GPS L1 DDR Desense 3 dB — PMIC 屏蔽罩顶部开窗(**C.3 原型案例**)

**基本信息**:
- 机型:O11U,阶段:P0.1
- 现象:GPS L1 DDR 场景 Desense ~3 dB
- 持续天数:**42 天**(设计级改版耗时)

**问题曲线**:
- 常规整改(Day 1-30):屏蔽罩加胶 / 接地加强 / 铜箔补强 / DDR 滤波 —— 均改善 < 1 dB
- 升级设计 review(Day 30-42):**发现 BOT 面 PMIC 屏蔽罩顶部有"工艺便利开窗"** —— 设计图纸上就有,不是装配问题
- 设计级改版(Day 42):**屏蔽罩顶部开窗取消,切换为积水铜箔** —— 恢复到限值内

**三要素**:
| 要素 | 内容 |
|---|---|
| 干扰源 | BOT 面 PMIC 屏蔽罩内宽带噪声(DDR + PMIC 叠加) |
| 受扰体 | GNSS L1(1561-1606 MHz,敏感度 -140 ~ -150 dBm)|
| 耦合路径 | 辐射 — 屏蔽罩顶部开窗 → PCB 另一面 → GPS 天线 |

**关键教训**:
1. **3 dB 对 GPS 是严重问题**,不是小问题
2. **常规整改 30 天无进展是强信号 —— 必须强制升级设计级 review**
3. **"工艺便利开窗"是隐蔽设计缺陷**,正常装配不等于设计合规
4. **多源矩阵命中时必须综合诊断**:本案例 DDR + PMIC + SHIELD_LEAK 三条映射都命中,SOP 间需相互引用(本 SOP 跨引用 [GL1-04](GL1-04.md) + NORMAL-07)

**时间护栏建议(反哺诊断流程)**:
- **普通整改 > 3 周无进展 → 强制升级到设计级 review**
- 这条应写进 `/diagnose` 流程的后续动作路由,避免 42 天耗时重现

## 八、附录

### 术语表

- **GNSS L1**:Global Navigation Satellite System L1 band(1561-1606 MHz),含 GPS L1 / BDS B1 / GLONASS G1 / Galileo E1
- **TTFF**:Time To First Fix,首次定位时间(冷启动 / 热启动分别测),受灵敏度恶化直接拉长
- **C/N0**:载波噪声比(dB-Hz),GPS 信号强度的直接度量,**是 GPS Desense 评估的首选指标**(比 RSSI 精细)
- **冷启动 / 热启动**:冷启动无星历 / 位置,热启动有星历;冷启动 TTFF 更长,对 Desense 更敏感
- **积水铜箔**:用铜箔填补屏蔽罩开窗的工艺,铜箔与屏蔽罩电气连接实现完整密封(C.3 最终方案)
- **槽天线(Slot Antenna)**:利用中框金属槽缝作为辐射体的天线形式,GPS / 5G 常用;槽口对 BOT 面噪声敏感
- **LNA**:Low Noise Amplifier,低噪放大器;GPS 接收链路前端必备,频谱测试时也需外加 LNA 提高底噪分辨
- **DDR**:Double Data Rate SDRAM,手机多为 LPDDR 版本
- **DVFS**:Dynamic Voltage and Frequency Scaling,动态调频调压

完整术语见 [knowledge/glossary.md](../../glossary.md)。
