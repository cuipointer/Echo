# SOP-LHB-01:系统时钟 (OSC / CPU / LCD MIPI) → LTE HB

**版本**:v0.9.0
**日期**:2026-05-06
**状态**:**方法论版(待现场复测)** — 从 placeholder v0.1 升级,基于 EMC 2024 B.1 + B.3 两个案例反哺 + W24-01 结构频段改写,**未经现场实测验证**

> **复测提醒**:LTE HB 覆盖范围大(2300-3700),各 Band 的时钟谐波命中路径不同,本 SOP 的命中表需按具体机型时钟规划 + 具体 Band 验算。

## 一、组合信息

### 干扰源(多源)

本 SOP 覆盖三类"系统时钟"源,它们的共同特征是"整数倍谐波落入 LTE HB"。现场诊断时应按场景收敛到其中之一或多源叠加。

| 源 | 代码 | 分类 | 典型基频 | 噪声来源 | 常见触发场景 |
|---|---|---|---|---|---|
| **系统主时钟 (OSC / XO)** | OS | 时钟 | 19.2 / 26 / 38.4 / 48 MHz | 晶振 + PLL 倍频 | 常态辐射,场景无关 |
| **CPU 时钟 (DVFS 档位)** | OS(归并) | 时钟 | 576 / 768 / 1024 / 1536 MHz 等 | CPU 核心时钟、总线时钟 | 高负载场景(FrontCam / Gaming / 拍照) |
| **LCD MIPI CLK** | LC | 显示 | 100-1000 MHz(依 panel 码率) | DSI Clock / Data 线开关 | 亮屏 / 高亮度 / 高分辨率 |

> CPU 时钟在矩阵中归并到 `OSC`(避免矩阵细分爆炸),但现场排查时必须独立对待 —— 因为 CPU 频率可通过 DVFS 动态切换,是诊断的关键手段。

### 受扰体

- **频段**:LTE HB + 5G NR Sub-6(含 B7 / B40 / B41 / B42 / B48 / N77 / N78 / N79)
- **代码**:LHB
- **频率范围**:2300-3700 MHz
- **敏感度要求**:-94 ~ -102 dBm
- **覆盖 Band 说明**:

| Band | 上行 / DIV 频率 (MHz) | 敏感区间说明 |
|---|---|---|
| B40 | 2300-2400 | 下沿易被 CPU 768M × 3 = 2304 命中 |
| B7 | 2500-2570(UL)/ 2620-2690(DL) | MIPI CLK 中高次谐波覆盖区 |
| B41 | 2496-2690 | WLAN 2.4G 邻频,时钟密集区 |
| B42 | 3400-3600 | MIPI 4-5 次谐波覆盖区 |
| B48 | 3550-3700 | 同上 |
| N77 | 3300-4200 | MIPI 3-5 次 / CPU 4 次谐波覆盖主区 |
| N78 | 3300-3800 | 同 N77 |
| N79 | 4400-5000 | CPU 768M × 6 / MIPI 5+ 次谐波区 |

### 耦合路径

- **主要类型**:**辐射耦合**(本 SOP 两大案例均为辐射)
- **次要类型**:传导耦合(MIPI 电源纹波经电源平面耦合,较少见)
- **机制**:
  - CPU 路径:CPU 屏蔽罩泄露 → 空间辐射 → LHB 天线接收;**场景激活(如 FrontCam)可放大辐射路径**(FPC 弯折 / 结构件有效辐射面增大)
  - MIPI 路径:DSI CLK / Data 线从屏 BTB / FPC 辐射 → LHB 天线
  - OSC/XO 路径:主时钟通过 PLL 扇出后的辐射,谐波次数高但单次能量小

### 矩阵元信息

- **优先级**:P1(LHB 整体优先级中,但单 Band 恶化可达 11-16 dB 属严重)
- **典型恶化量**:3-8 dB(常态);场景激活下可达 **11-16 dB**(本 SOP 两大案例实测)
- **快速诊断提示**:
  - 怀疑 CPU:切换 CPU DVFS 档位,看干扰频点是否移动
  - 怀疑 MIPI:灭屏 + 改亮度 + 改 MIPI 码率(分辨率 / 帧率),看改善
  - 怀疑 OSC:极少见的"与所有场景无关"恒定 spur

## 二、理论预判

### 谐波命中计算

**关键:LTE HB 跨度大(2300-3700 + N79 到 5000),不同源的不同次谐波都可能命中。必须按机型实际时钟规划做命中表,不能套用。**

#### CPU 时钟 × N(本 SOP 案例 1 主路径)

| CPU 频率 | × 3 | × 4 | × 5 | × 6 | 命中 Band |
|---|---|---|---|---|---|
| 576 MHz | 1728 | 2304 | 2880 | 3456 | ×4→B40 / ×5→B41 / ×6→N78 |
| **768 MHz** | 2304 | 3072 | 3840 | 4608 | **×3→B40 ✓(案例 1)** / ×4→N78 / ×5→N79 下沿 / ×6→N79 |
| 1024 MHz | 3072 | 4096 | 5120 | 6144 | ×3→N78 / ×4→N79 |
| 1536 MHz | 4608 | 6144 | — | — | ×3→N79 |

#### LCD MIPI CLK × N(本 SOP 案例 2 主路径)

| MIPI CLK | × 3 | × 4 | × 5 | 命中 Band |
|---|---|---|---|---|
| 600 MHz | 1800 | 2400 | 3000 | ×4→B40 上沿 |
| 800 MHz | 2400 | 3200 | 4000 | ×3→B40 / ×4→B42/N78 |
| **900 MHz** | 2700 | 3600 | 4500 | ×4→B48 / ×5→N79 |
| 1000 MHz | 3000 | 4000 | 5000 | **×4→N77 ✓(案例 2 方向)** |
| 1200 MHz | 3600 | 4800 | — | ×3→B48 / ×4→N79 |

> **案例 2 的 MIPI CLK 具体频率文档未定量**,但 N77(3300-4200)被命中的规律是"MIPI CLK × 3~5 次落入 N77"。使用 `python3 tools/harmonic_calc.py <MIPI_CLK> 4 3300 4200` 按机型实测频率验证。

#### OSC / XO × N(极高次谐波,密集但单次能量小)

- 19.2 MHz × 120 = 2304 MHz(命中 B40,与 CPU 768M×3 同频点,需频谱 fine-tune 才能区分)
- 19.2 MHz × 156 = 2995 MHz(B42 区域)
- 19.2 MHz × 198 = 3802 MHz(N77 上沿 / N79 下沿)
- 38.4 MHz × 78 = 2995 MHz
- 38.4 MHz × 99 = 3802 MHz

> XO 极高次谐波是"底色",能量通常较弱;若现场看到强 spur,优先怀疑 CPU/MIPI(能量大得多)。

### 设计审查必查项

1. **CPU / SoC 屏蔽罩完整性**:焊点 / 点胶量 / 中框接地(案例 1 根因所在)
2. **MIPI 通路串联器件预留**:通路是否预留 10 nH 电感 / 磁珠封装位(案例 2 首选整改位,极低成本)
3. **CPU 时钟规划**:主 CPU DVFS 档位 × 2-6 次谐波对 B40/B7/N77/N78/N79 的命中表
4. **MIPI CLK 规划**:panel 码率 × 3-5 次对 N77/N79 的命中关系;SSC 是否可开
5. **LCD FPC 布线 / 屏蔽**:FPC 屏蔽层接地完整性、与天线区域距离
6. **天线隔离**:LHB 天线与 CPU / LCD 连接器的物理距离
7. **场景激活路径风险**(案例 1 教训):FrontCam 激活时前摄 FPC 弯折是否改变辐射结构;查早期设计是否识别此风险

## 三、软件排查步骤

### 步骤 1:场景复现(**关键 — 定量多场景贡献**)

**目标**:区分"常态 / CPU 场景激活 / 亮屏"各自贡献,为后续收敛源提供依据

**操作**:
1. **Normal 基线**:关屏 + 低负载,测 LHB 各 Band 灵敏度,记为基线
2. **FrontCam 场景**:打开前摄 App(高 CPU 负载、FPC 激活),保持亮屏,测灵敏度
3. **BrightScreen 场景**:不开摄像头,屏亮到最大 + 高分辨率,测灵敏度
4. 填写对比表:

| 场景 | B40 (dB) | N77 (dB) | 其他 Band | Δ vs Normal |
|---|---|---|---|---|
| Normal(灭屏 + 空载) | — | — | — | 基线 |
| FrontCam | — | — | — | — |
| BrightScreen(亮屏) | — | — | — | — |
| FrontCam + BrightScreen | — | — | — | — |

**预期结果**:定量给出"CPU 相关 / MIPI 相关 / 叠加"三种路径各自的 dB 贡献。**两类场景的 Desense 差值是后续决策的关键输入**:

- FrontCam Δ > BrightScreen Δ → 倾向案例 1 路径(CPU)
- BrightScreen Δ > FrontCam Δ → 倾向案例 2 路径(MIPI)
- 两者都大且可线性相加 → 双源叠加,进入步骤 2.6

### 步骤 2:干扰源确认

**目标**:在步骤 1 定性的基础上进一步收敛

**操作**(按零成本顺序):

1. **灭屏测试**(adb shell input keyevent 26):
   - 干扰完全消失 → MIPI / LCD 路径为主
   - 干扰部分残留 → CPU / OSC 残留 + 背光 PWM 可能

2. **CPU DVFS 切换**:强制固定 CPU 到不同档位(576 / 768 / 1024 MHz),观察干扰频点:
   - 频点随 CPU 频率按整数倍移动 → CPU 时钟谐波(案例 1 模式)
   - 频点不动 → 非 CPU

3. **亮度调节**:调到最低亮度 vs 最高亮度,观察:
   - 与亮度正相关(且线性)→ 背光 PWM 相关(LCD,非 LHB 主因)
   - 与亮度无关但与"是否亮屏"强相关 → MIPI CLK 相关(案例 2 模式)

4. **MIPI SSC on/off**:若平台支持动态切换 SSC:
   - SSC on 后改善 2-5 dB → MIPI 确认
   - SSC on 无效 → MIPI 排除或 SSC 深度不够

**预期结果**:收敛到 CPU / MIPI / 两者其一路径。

### 步骤 2.5:子功能逐项排查

**触发**:步骤 2 无法单独确认,尤其 FrontCam 场景叠加了 CPU + Camera MIPI + 前摄 FPC 多个因子

**操作**:

- **CPU 相关细分**(若走案例 1 路径):
  - 固定 CPU 在 768 MHz vs 1024 MHz vs 576 MHz,看 B40 恶化是否随档位移动命中频点
  - 后台杀掉其他 App,保留纯 Camera Preview,隔离 FrontCam 的"CPU 占用部分"
- **MIPI 相关细分**(若走案例 2 路径):
  - 改 panel 码率:1080p@60 vs 1080p@90 vs 720p@60,看 MIPI CLK 改变后 N77 频点移动
  - 改 MIPI Drive Strength(若平台支持)
- **FrontCam 场景进一步细分**(案例 1 特有):
  - Camera Preview vs Photo Capture vs Video Record,看哪个子动作贡献最大
  - 目的:区分"CPU 负载引起的时钟抬升" vs "FrontCam FPC 激活放大辐射路径"

**预期结果**:隔离单一子功能的 Desense 贡献。

### 步骤 2.6:多源叠加排查

**触发条件**:步骤 1 看到 FrontCam + BrightScreen 叠加场景恶化 > 两者单独之和,或两者各自都贡献 > 3 dB

**操作**:按 [`_template.md` 步骤 2.6](../_template.md) 多源叠加排查法

候选源枚举:
- H1:CPU 时钟谐波(768M × 3 = 2304 命中 B40)
- H2:MIPI CLK 高次谐波(N77 区域)
- H3:CPU 屏蔽罩 + 前摄 FPC 辐射路径协同(案例 1 机制)
- H4:MIPI SSC 未开启(理论可改善但需平台支持)

正交验证顺序:灭屏(关 H2)→ DVFS 固定低频(关 H1)→ 关 FrontCam(关 H3)。

### 步骤 3:频率验证

**目标**:频谱仪 + 谐波计算双向验证

**操作**:
1. 读取当前 CPU 频率 / MIPI CLK 频率(系统 log 或平台命令)
2. 用 `python3 tools/harmonic_calc.py <基频> <次数> <Band 下沿> <Band 上沿>` 计算命中情况
3. 频谱仪在对应 Band 观察谱线,**注意区分**:
   - 单根强 spur → CPU / MIPI 特定谐波
   - 密集梳状 → XO 超高次(次数 > 100)
4. DVFS 切档时观察谱线移动:
   - 移动量 = Δf_CPU × N → 反推出命中次数 N

**预期结果**:谐波计算与频谱实测一致,锁定具体源 + 次数。

### 步骤 4:软件规避尝试

**目标**:先尝试软件措施(LHB 软件措施效果通常有限,案例 1 与案例 2 最终都走硬件)

**操作**:
1. **MIPI SSC**:开启并调大调制深度(±1% ~ ±3%),对 MIPI 相关改善 2-5 dB
2. **CPU DVFS 策略**:避开 768 MHz 档位(若项目允许,代价是性能)
3. **MIPI 码率调整**:改 panel 码率避开命中点(需 Display 团队配合)
4. **数字滤波 NV 调整**:基带侧 NV 参数微调,通常仅 1-2 dB
5. **WiFi / LTE Band 避让**:极端情况下业务层避开被干扰的 Band(权宜)

**预期结果**:LHB 场景通常软件改善 1-5 dB,**对 CPU 屏蔽泄露路径基本无效,必须走硬件**。这是 LHB 与 W24 的关键区别。

## 四、硬件排查步骤(主路径 — 本 SOP 两大案例都在此收官)

**触发条件**:软件措施改善不足(LHB 几乎必然触发)

### 步骤 1:近场扫描 + 路径判定

**目标**:判别案例 1 路径(CPU)vs 案例 2 路径(MIPI),决定硬件策略

**操作**:
1. **近场探头扫描**:
   - 扫描 CPU 屏蔽罩边缘 / 焊点 / 开窗 → 强点 = CPU 路径(案例 1)
   - 扫描屏 BTB / LCD FPC / MIPI 连接器 → 强点 = MIPI 路径(案例 2)
   - 扫描前摄 FPC / 结构件开孔 → 强点 = FPC 激活放大路径
2. **临时屏蔽 / 拉距测试**:
   - 铜箔临时封 CPU 屏蔽罩缝隙:改善 ≥ 3 dB → 案例 1 路径确认
   - 外接 LHB 天线拉远 LCD 区域:改善 ≥ 3 dB → 案例 2 路径确认
3. **天线隔离度测试**:LHB 天线与 CPU / LCD 的隔离度与预期偏差

**预期结果**:定位主路径,选择步骤 2 或步骤 3。

### 步骤 2:**首推 — MIPI 通路串 10 nH 电感(案例 2 路径,6 天快速闭环)**

**触发**:路径判定指向 MIPI;或即使 CPU 路径为主,MIPI 也是次要贡献时

**动作**:
- **MIPI CLK / Data 线上串 10 nH 电感**(推荐封装 0201/0402,电流规格覆盖 MIPI 差分对峰值)
- 选型要点:
  - 自谐振频率 (SRF) > 5 GHz
  - DCR 尽量小(< 500 mΩ),避免 MIPI 眼图恶化
  - 10 nH 是 O10 案例的实测最优值;其他机型应在 4.7 / 6.8 / 10 / 15 nH 扫参
- **MIPI 数据完整性验证**:电感后重测 MIPI 眼图(DSI CTS),确保 HS-Clock 满足规范
- 预期改善:**6-11 dB**(O10 案例闭环值)

**为何首推**:成本极低(BOM 0.5 分钱以内)、改版周期短(可换料验证)、风险可控(眼图可量化)—— **案例 2 O10 机型 6 天快速闭环的关键**。

### 步骤 3:**CPU 屏蔽加强 — 全方位导电泡棉(案例 1 路径)**

**触发**:路径判定指向 CPU 屏蔽泄露;FrontCam 场景 Desense 显著高于 BrightScreen

**动作**:
- **中框增加全方位导电泡棉压紧 CPU 屏蔽罩与中框**(包围性屏蔽,阻断各方向辐射泄露)
- 泡棉选型:
  - 导电布包泡棉,压缩后接触阻抗 < 100 mΩ
  - 压缩量 30-50%(避免永久形变)
  - 覆盖屏蔽罩四周 + 关键焊点
- **配合动作**:
  - 加强屏蔽罩焊接(点胶均匀性)
  - 中框镭雕面 / 导电漆接触面优化
- 预期改善:**8-16 dB**(O11 案例闭环值,FrontCam 从 16 dB → 内限)

**成本 / 工期**:结构件改模具 + 试装,典型 10-20 天(O11 案例 17 天闭环);成本相比 PCB 改版可控,但比串电感重。

### 步骤 4:PCB 层叠 / 走线改版(兜底)

**触发**:步骤 2 / 3 改善不足

**整改点 / 预期改善表**:

| 整改点 | 措施 | 预期改善 | 适用路径 |
|---|---|:---:|---|
| **MIPI 串 10 nH 电感** | 通路串磁性元件 | **6-11 dB** | 案例 2(MIPI) |
| **CPU 导电泡棉屏蔽** | 全方位包围 | **8-16 dB** | 案例 1(CPU) |
| CPU 屏蔽罩焊接 | 焊点加密 / 点胶补强 | 2-5 dB | 案例 1 |
| MIPI 包地过孔 | FPC / PCB 侧加包地 | 2-4 dB | 案例 2 |
| LCD FPC 屏蔽层 | 加屏蔽层 / 接地 | 2-5 dB | 案例 2 |
| LHB 天线与 CPU/LCD 距离 | 布局优化 | 1-4 dB | 两者 |
| LHB 前端加滤波器 | SAW / LC 带通 | 3-8 dB(但插损增大) | 两者(最后手段) |
| PCB 层叠调整 | 缩小环路 / 加地层 | 2-5 dB | 两者(代价大) |

**预期结果**:综合改善到内部限值(LHB ≤ 4 dB)。

## 六、典型案例

### 案例 1:O11 B40 DIV FrontCam 场景 16 dB(CPU 时钟路径)

**定位**:本 SOP 的"CPU 时钟 + 场景放大"标杆案例。

**来源**:EMC 2024 B.1 / [O11-LHB-CPU-clock-B40.md](../../cases/O11-LHB-CPU-clock-B40.md)

**关键数据**:
- Band:B40 DIV(2300-2400 MHz)
- 场景:FrontCam 触发
- Desense:16 dB(单场景严重级)
- 持续:17 天
- **谐波计算**:CPU 768 MHz × 3 = **2304 MHz**,正中 B40 低端 ✓

**三要素**:
- 干扰源:CPU 768M 时钟三次谐波
- 受扰体:B40 DIV(弱信号敏感)
- 路径:CPU 屏蔽罩泄露 + **FrontCam 场景放大辐射路径**(FPC 弯折 / 结构有效辐射面增大)

**最终整改**:中框增加**全方位导电泡棉屏蔽**(阻断 CPU 区域泄露)。

**复用启示**:
1. FrontCam 场景不只激活新源,也**放大既有源路径** — 场景 Desense 的关键机制
2. 软件不可调 CPU 时钟时,必须走硬件屏蔽
3. 设计 review 必须覆盖**所有整数次谐波 × 所有 Band**,不能只看低次

### 案例 2:O10 N77 亮屏 11 dB(MIPI 路径,6 天快速闭环标杆)

**定位**:本 SOP 的"MIPI + 低成本硬件"快速闭环标杆。

**来源**:EMC 2024 B.3 / [O10-LHB-MIPI-brightness.md](../../cases/O10-LHB-MIPI-brightness.md)

**关键数据**:
- Band:N77(3300-4200 MHz)
- 场景:亮屏触发
- Desense:11 dB
- 持续:**6 天**(熟路快速闭环)
- **谐波方向**:MIPI CLK 高次谐波(× 3-5 次)覆盖 N77;具体频率需按 panel 码率实测

**三要素**:
- 干扰源:LCD MIPI CLK 高频谐波
- 受扰体:N77(亮屏触发 MIPI 工作)
- 路径:辐射 — MIPI 谐波从屏 BTB / FPC 辐射到 N77 天线

**最终整改**:**MIPI 通路串 10 nH 电感**(抑制高频噪声)。

**复用启示**:
1. **"MIPI 串 10 nH"应是 LHB MIPI 路径的首选动作**:成本极低、验证快、风险可控
2. SOP 覆盖度与耗时成强反比(6 天 vs C.2 的 42 天)
3. MIPI CLK 的 3-5 次谐波密集覆盖 3-5 GHz 区间,是 N77/N78/N79 / WiFi 5G 共有风险

### 两案例对比(分源 / 分场景)

| 维度 | 案例 1(CPU) | 案例 2(MIPI) |
|---|---|---|
| 主源 | CPU 768M 时钟 | LCD MIPI CLK |
| 场景 | FrontCam(CPU 高负载) | 亮屏(任何 MIPI 工作) |
| 命中 Band | B40 下沿 | N77 |
| 谐波 | × 3 低次 | × 3-5 中次 |
| 主路径 | CPU 屏蔽罩泄露 + 场景放大 | MIPI FPC 辐射 |
| 主整改 | 全方位导电泡棉 | 串 10 nH 电感 |
| 成本 | 结构模具改版 | BOM 0.5 分钱 |
| 闭环天数 | 17 天 | 6 天 |
| 软件可解 | 不可调(CPU 时钟固定) | 有限(SSC 可助 2-5 dB) |

**两案例互补性**:CPU 路径和 MIPI 路径机制不同、整改手段不同,现场可能单独出现也可能叠加(步骤 2.6 覆盖)。本 SOP 的软件步骤 1-3 用多场景对比定性区分,硬件步骤 1 用近场扫描定量确认,然后分别走步骤 2(MIPI)或步骤 3(CPU)。

### 术语表

- **Desense**:De-sensitization,灵敏度恶化
- **SSC**:Spread Spectrum Clocking,展频时钟(MIPI / DDR 常用)
- **DVFS**:Dynamic Voltage and Frequency Scaling,CPU 动态调频调压
- **MIPI / DSI**:Display Serial Interface,LCD 高速串行接口
- **BTB**:Board-to-Board 连接器
- **FPC**:Flexible Printed Circuit,柔性电路板
- **XO**:Crystal Oscillator,晶体振荡器
- **DIV / Diversity**:分集接收链路(对弱信号敏感)
- **LHB**:LTE High Band,含 LTE HB + 5G NR Sub-6 中高频

完整术语见 [knowledge/glossary.md](../../glossary.md)。
