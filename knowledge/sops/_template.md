### 步骤 2.6：多源叠加排查法(可选,适用于宽带 / 多场景 Desense)

**触发条件**:满足以下任一
- 步骤 2.5 子功能逐项排查后,单一关闭动作无法消除 Desense(仅部分改善)
- 现象表现为多场景共同恶化但幅度差异明显(如 EMC 2024 C.2 案例,前后摄场景 7~11 dB 不均)
- 同一受扰体在不同场景下表现不同,且关闭任一场景仍有显著残余

**操作**:

1. **枚举候选源**:结合 /diagnose Step 3 宽窄带判别保留的源列表,列出 2~4 个怀疑源(H1, H2, H3, ...)
2. **单源隔离测试**(依次 / 轮流):
   - 关 H1 → 测 Desense 改善 ΔdB₁
   - 关 H2 → 测 Desense 改善 ΔdB₂
   - 关 H3 → 测 Desense 改善 ΔdB₃
3. **组合关断测试**:
   - 同时关 H1+H2 → 测总改善 ΔdB₁₂
   - 比较 ΔdB₁₂ 与 ΔdB₁+ΔdB₂:
     - 接近 → 两源独立叠加(典型线性)
     - 明显小于 → 两源有相同路径或互相掩盖
     - 明显大于 → 可能存在非线性耦合
4. **决策**:按 ΔdB 大小排序贡献,优先整改贡献最大的源;若多源相近则综合整改

**预期结果**:定位所有显著贡献源及其贡献量,避免单源整改后仍有残余

**典型案例**:[knowledge/cases/EMC-2024-Desense-triage.md](../cases/EMC-2024-Desense-triage.md) C.2(O11U MHB 7-11 dB,CPU 屏蔽 + 主摄 FPC 两源叠加,42 天耗时的主因是多次分离验证)
