# SOP-W24-09:屏蔽泄露 → WiFi 2.4G

**版本**:v0.9.0
**日期**:2026-05-06
**状态**:**方法论版(待现场复测)** — 从 placeholder v0.1 升级,基于 EMC 2024 A.2 案例反哺 + W24-03 结构参照,**未经现场实测验证**

> **复测提醒**:屏蔽罩泄露幅度与机型屏蔽罩设计 / 装配一致性强相关,本 SOP 的整改方向为方法论推导,现场需按具体屏蔽罩布局验证。

---

## 一、组合信息

### 干扰源
- **模块**:屏蔽泄露(SHIELD_LEAK)—— 屏蔽罩内部宽带底噪,通常包含 CPU / PMIC / DDR 等主芯片综合噪声
- **代码**:SL
- **分类**:射频
- **噪声来源**:屏蔽罩内部多源叠加底噪(CPU 开关噪声 / DDR 时钟 / PMIC 纹波 / 主 SoC 综合辐射)从密封不良处泄露
- **基频范围**:宽带(无单一基频,频谱特征为底噪抬升而非单点谱线)
- **典型干扰**:WiFi 2.4G 全频段信道平坦度恶化,非单点谐波命中

### 受扰体
- **频段**:WiFi 2.4G
- **代码**:W24
- **频率范围**:2412-2484 MHz(全频段,ch1-ch13)
- **敏感度要求**:-82 ~ -90 dBm

### 耦合路径
- **主要类型**:**辐射耦合**(屏蔽罩缝隙 / 开窗 / 接合面间隙 → WiFi 天线)
- **次要类型**:结构性泄露(屏蔽罩与中框接合不良导致中框腔体二次辐射)
- **机制**:
  - 屏蔽罩等效为**槽天线**:密封不良处的缝隙 / 开窗在宽带底噪激励下成为有效辐射源
  - **接地点密度不足**:屏蔽罩与 PCB 接地焊点间距 > λ/20 时,接地完整性失效,高频噪声从焊点间隙泄露
  - **贴合间隙**:屏蔽罩与中框 / 盖板贴合不严,内部噪声从缝隙扩散到天线区域
  - **chain 差异特征**:双链路天线中,靠近 CPU 屏蔽罩的 chain 明显劣化,远离的 chain 几乎不受影响(典型诊断信号)

### 矩阵元信息
- **优先级**:P2(问题发生率低于 DDR / CPU 时钟,但单次闭环耗时长,软件不可解)
- **典型恶化量**:3-10 dB(信道平坦度差形式,非单点恶化)
- **快速诊断提示**:**chain 间对比 + 全信道扫描看平坦度**(关键判据:平坦度 ≥ 3 dB 即怀疑宽带泄露)

## 二、理论预判

### 宽带泄露机制分析

与单点谐波命中不同,屏蔽泄露的频谱特征是**底噪抬升**:

| 机制 | 说明 |
|---|---|
| **槽天线效应** | 屏蔽罩上任何 ≥ λ/20 的缝隙 / 开窗都会成为槽天线,2.4G(λ ≈ 125 mm)对应的敏感缝隙尺寸 ≥ 6 mm |
| **接地失效** | 屏蔽罩接地焊点间距 > λ/20 时,焊点间的屏蔽罩边缘不再是"理想接地",高频噪声从焊点间隙辐射 |
| **内部底噪源** | CPU / DDR / PMIC 在高负载时,在屏蔽罩内部产生连续宽带底噪,而非某个单点强谱线 |
| **多源叠加** | 屏蔽罩泄露通常伴随其他干扰源(DDR 谐波 / PMIC 纹波),需用多源叠加法区分 |

**关键区别**:
- **窄带谐波命中**:频谱上看到单根强谱线 → 走 W24-01/W24-03 路径
- **宽带底噪抬升**:频谱底噪整体上抬,无特定谱线 → 走本 SOP

### 设计审查必查项

1. **屏蔽罩接地点密度**:检查焊点间距,2.4G 要求 ≤ 6 mm(≤ λ/20)
2. **屏蔽罩与天线物理距离**:必须做 overlay 检查,靠近天线(< 10 mm)的屏蔽罩必须有 chain 对比数据
3. **屏蔽罩开窗必要性**:任何开窗(散热 / 装配孔 / 测试点)都要评估必要性,非必要开窗必须填充导电材料
4. **屏蔽罩与中框贴合**:中框镭雕面平整度 / 导电泡棉厚度 / 压缩量 / 屏蔽罩点胶均匀性
5. **chain 对比数据**:双链路天线必须有 chain0 vs chain1 的灵敏度对比,差异 > 2 dB 即触发屏蔽罩审查
6. **屏蔽罩层级结构**:主屏蔽罩(CPU) / 子屏蔽罩(PMIC)是否存在缝隙叠加
7. **内部噪声源控制**:屏蔽罩内部 DDR / CPU 的滤波是否做到位,减小激励幅度

**参考案例**:
- [O11-W24-shield-chain1.md](../../cases/O11-W24-shield-chain1.md) — O11 chain1 CPU 屏蔽罩泄露(平坦度 6.2 dB,本 SOP 首源案例)
- EMC 2024 C.2 — O11U CPU 屏蔽罩 + 主摄 FPC MHB 多源叠加(屏蔽罩机制一致)

## 三、软件排查步骤

### 步骤 1:场景复现

**目标**:确认屏蔽泄露 Desense 可复现,并采集**信道平坦度**基线

**操作**:
1. 双链路分别测量 WiFi 2.4G 全信道(ch1-ch13)灵敏度 → **chain0 基线 / chain1 基线**
2. 计算各 chain 信道间**平坦度差** = max(信道) - min(信道)
3. 对比 chain0 vs chain1 的平坦度差(**本 SOP 的核心入口判据**)

**预期结果**:
- 若单 chain 平坦度 ≥ 3 dB → 宽带泄露候选(进入本 SOP)
- 若 chain0 与 chain1 平坦度差异显著 → 屏蔽泄露嫌疑加大(chain 间差异判据)

### 步骤 2:干扰源确认(内部源 vs 屏蔽结构)

**目标**:区分"是屏蔽罩内部噪声源增强"还是"屏蔽结构本身泄露"

**操作**:
1. **关闭 DDR 高频模式 / DVFS 降频**:观察平坦度变化
   - 改善明显 → 内部 DDR 为主要贡献源
   - 改善不明显 → 屏蔽结构本身泄露(**进入硬件排查**)
2. **关闭 CPU 高负载 / 空载**:观察平坦度变化
   - 改善明显 → CPU 噪声为主要贡献源
   - 改善不明显 → 结构性泄露(**进入硬件排查**)
3. **关闭 PMIC 某路 DCDC**(如不影响业务):观察
4. **综合判断**:若三种操作均无明显改善,屏蔽罩结构自身就是主要泄露路径

**预期结果**:区分"内部源驱动"和"屏蔽结构失效"两类机制

### 步骤 2.5:信道平坦度诊断(强化判据)

**目标**:量化宽带泄露程度,确定进入硬件流程的必要性

**判据**(来自 EMC 2024 A.2 O11 案例):

| 信道平坦度 | 诊断结论 | 后续动作 |
|---|---|---|
| < 3 dB | 基本正常,不是宽带泄露 | 回到窄带谐波路径(W24-01/03) |
| 3-6 dB | 宽带泄露嫌疑 | 继续本 SOP,做近场定位 |
| **≥ 6 dB** | **严重屏蔽泄露**(O11 A.2 案例线) | 直达硬件整改,屏蔽罩加固 |

**操作**:
1. 全信道扫描出平坦度曲线图
2. 对比两个 chain 的曲线形态(是否 chain1 > chain0?)
3. 记录平坦度最差的信道位置(中心 / 边缘)

**预期结果**:定位平坦度恶化区间,输出"平坦度 X dB @ chain Y"

### 步骤 2.6:多源叠加排查

**触发条件**:步骤 2 改善部分但未到限值内,怀疑多源叠加

**操作**:按 [`_template.md` 步骤 2.6](../_template.md) 多源叠加排查法

候选源枚举:
- H1:CPU 屏蔽罩泄露(本 SOP 主假设)
- H2:DDR 时钟宽带噪声(屏蔽罩内部源)
- H3:PMIC 电源 SSN(屏蔽罩内部源)
- H4:主摄 FPC / B2B 连接器处结构性泄露
- H5:中框接地完整性问题

**预期结果**:拆分各源单独贡献(ΔdB)

### 步骤 3:频谱验证(近场)

**目标**:在屏蔽罩表面直接采集近场,定位泄露点

**操作**:
1. 近场探头(H-probe / E-probe)扫描屏蔽罩**四条边缘 / 四个角 / 开窗处**
2. 观察 2.4G 频段(2412-2484 MHz)的底噪幅值分布
3. 对比高负载(压测)vs 空载的近场差异
4. 锁定"热点"位置 —— 底噪最高的边缘 / 接合点

**预期结果**:输出"屏蔽罩泄露热点坐标",作为硬件整改的定位输入

### 步骤 4:软件规避尝试

**目标**:确认软件措施空间

**现实**:**屏蔽结构泄露,软件基本无效**(A.2 案例已验证)

可能有小幅改善的软件措施:
1. DDR DVFS 降频(降低内部激励)→ 改善 < 2 dB
2. CPU 调度策略优化(降低峰值负载)→ 改善 < 1 dB
3. WiFi 信道避让(业务层权宜)→ 非根治

**预期结果**:软件改善上限通常 ≤ 2 dB,不足以解决 ≥ 6 dB 的严重泄露 → **直接转硬件排查**

## 四、硬件排查步骤(主路径)

**触发条件**:软件措施无效(本 SOP 的常态)

### 步骤 1:近场定位

**目标**:精确定位屏蔽罩上的泄露点

**操作**:
1. 拆机 / 半拆机状态,探头扫描屏蔽罩表面(**注意拆机可能改变屏蔽状态**)
2. 重点关注:
   - 屏蔽罩四条边缘接合线
   - 点胶 / 焊接边缘
   - 开窗(散热孔 / 装配孔 / 测试点)
   - 屏蔽罩与中框接合面
   - 靠近天线一侧(chain1 方向)
3. 记录泄露点相对坐标(与天线距离)

**预期结果**:泄露热点定位精度 < 5 mm

### 步骤 2:屏蔽罩整改(核心措施)

**目标**:针对泄露点做屏蔽加固

| 整改点 | 措施 | 预期改善 |
|---|---|:---:|
| 屏蔽罩缝隙 / 开窗 | 铜箔贴覆 / 导电胶填充(临时验证) | 2-6 dB |
| 屏蔽罩与中框贴合 | 导电泡棉加厚 / 压缩量加大 | 2-5 dB |
| 接地点密度 | 屏蔽罩补打接地焊点(间距 ≤ 6 mm) | 3-6 dB |
| 点胶工艺 | 改善点胶均匀性 / 减小溢胶(见 EMC C.2 案例) | 1-3 dB |
| 非必要开窗 | 取消 / 改小 / 填充 | 2-5 dB |

**注**:以上 dB 值为方法论推导,实测值以 O11 A.2 最终数据为准(13 天整改周期)。

**预期结果**:综合改善到 ≤ 3 dB 平坦度(内部限值)

### 步骤 3:结构级整改

**触发条件**:步骤 2 不足,需要动结构

**操作**:
1. 中框与屏蔽罩接合面优化(中框镭雕面平整度 / 导电涂层)
2. 屏蔽罩分区重设计(避开天线投影区)
3. 天线位置微调(与屏蔽罩距离增加)
4. 屏蔽罩层级重构(增加子屏蔽罩隔离 DDR / CPU)

**预期结果**:结构级整改需要版本级改板,通常纳入 P2/P3 阶段

### 案例 1:O11 chain1 Normal 信道平坦度 6.2 dB — CPU 屏蔽罩泄露(本 SOP 首源案例)

**文件**:[O11-W24-shield-chain1.md](../../cases/O11-W24-shield-chain1.md)
**来源**:EMC 2024 A.2
**阶段**:P1
**持续**:13 天
**结果**:硬件整改闭环(P2 回归验证屏蔽罩加固)

**关键过程**:

| 环节 | 内容 |
|---|---|
| 现象 | 2.4G WiFi **chain1** Normal 信道间平坦度最差 **6.2 dB**,全频段宽带劣化 |
| 宽窄带判别 | "信道平坦度差"→ 全频段宽带特征(区别于单频点谐波命中) → 排除窄带谐波,保留:平台泄露 / 电源 SSN / 屏蔽不良 |
| 决策树 | `W24` + 宽带 → 候选源 `SHIELD_LEAK / PMIC / DDR`;chain1 靠近 CPU 位置 → H1:CPU 屏蔽罩泄露 |

| 根因 | CPU 屏蔽罩内部噪声从密封不良处辐射泄露,chain1 因物理靠近 CPU,受影响显著 |
| 解决 | **屏蔽罩加固**(屏蔽罩与中框贴合优化 + 接地点密度提升) |

- **6.2 dB 平坦度阈值**的诊断意义 → 已固化为"≥ 6 dB 严重屏蔽泄露"判据(步骤 2.5)
- **chain 间差异**作为宽带屏蔽泄露的典型特征 → 已写入 Section 二·理论预判
- **屏蔽罩密封性检查 → 接地点密度优化**作为硬件主路径 → Section 四
- **matrix.yaml 固化**:新增 `SHIELD_LEAK → W24 = W24-09`(v2.1.0)

## 八、附录

### 术语表

- **屏蔽罩(Shielding Can)**:PCB 上覆盖在主芯片(CPU / PMIC 等)上方的金属罩,起电磁屏蔽作用,通常焊接或卡扣固定
- **chain 隔离度**:双链路天线方案中,两条接收链路(chain0 / chain1)之间的隔离度,反映物理位置和耦合路径独立性
- **信道平坦度(Channel Flatness)**:WiFi 全信道灵敏度的最大值与最小值之差,是宽带干扰的核心判据
- **槽天线等效**:屏蔽罩上的缝隙 / 开窗在缝隙尺寸接近 λ/20 时等效为辐射天线,是屏蔽泄露的物理机制
- **接地点密度**:屏蔽罩与 PCB 焊接接地点的空间密度,间距要求 ≤ λ/20(2.4G 对应 ≤ 6 mm)
- **SHIELD_LEAK**:矩阵中的干扰源代码(SL),分类为射频
- **Normal Desense**:空载 / 基线场景下的灵敏度劣化,需优先达标才能评估具体场景干扰

完整术语见 [knowledge/glossary.md](../../glossary.md)。
