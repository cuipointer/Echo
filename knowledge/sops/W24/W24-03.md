**版本**:v0.9.0
**日期**:2026-05-06
**状态**:**方法论版(待现场复测)** — 从 placeholder v0.1 升级,基于 EMC 2024 C.1/C.2 案例反哺 + W24-01 结构参照,**未经现场实测验证**

---

## 一、组合信息

### 干扰源
- **模块**:DDR(Double Data Rate SDRAM,含 DDR Controller + DDR PHY)
- **代码**:DD
- **分类**:存储
- **噪声来源**:内存时钟、数据线开关噪声、DDR PHY 训练时的突发噪声
- **基频范围**:200-933 MHz(典型 LPDDR5 / LPDDR4X / LPDDR4)
- **典型干扰**:宽带高频噪声覆盖多个频段;特定 DDR 频率谐波命中 WiFi 2.4G

### 受扰体
- **频段**:WiFi 2.4G
- **代码**:W24
- **频率范围**:2412-2484 MHz
- **敏感度要求**:-82 ~ -90 dBm

### 耦合路径
- **主要类型**:**辐射耦合**(DDR 屏蔽罩缝隙 / CPU 屏蔽罩 / 结构性路径)
- **次要类型**:**传导耦合**(电源平面 DDR 供电纹波)
- **机制**:
  - 辐射路径:DDR 高频时钟噪声从屏蔽罩缝隙 / 开窗 / 接地不良处泄露 → WiFi 天线接收
  - 结构性路径:如前摄破洞 / FPC 缝隙导致噪声从主板腔体逸出(见 [O11-DDR-LLB-aperture.md](../../cases/O11-DDR-LLB-aperture.md))
  - 传导路径:DDR VDD 电源纹波经电源平面耦合到 WiFi 前端

### 矩阵元信息
- **优先级**:P1
- **典型恶化量**:3-8 dB(典型 DDR 场景),部分叠加场景可达 7-11 dB
- **快速诊断提示**:**停止下载 / 负载**(降低 DDR 带宽)

## 二、理论预判

### 谐波命中计算

DDR 基频 200-933 MHz,2-12 次谐波可能命中 WiFi 2.4G:

| DDR 基频 | 谐波次数 | 命中频点 | 是否命中 2.4G(2412-2484) |
|---|:---:|---|:---:|
| 200 MHz | 12 | 2400 MHz | ✓ 低端 |
| 300 MHz | 8 | 2400 MHz | ✓ 低端 |
| 400 MHz | 6 | 2400 MHz | ✓ 低端 |
| 600 MHz | 4 | 2400 MHz | ✓ 低端 |
| 800 MHz | 3 | 2400 MHz | ✓ 低端 |
| 933 MHz | 2.6 | 2425 MHz | ✓ 中段 |

**结论**:主流 DDR 频率都存在 2-12 次谐波命中 WiFi 2.4G 的可能;DDR 频率越高,谐波越低次能量越强,危害越大。

### 设计审查必查项

1. **CPU / DDR 屏蔽罩完整性**:屏蔽罩焊点 / 开窗 / 胶量
2. **DDR 电源滤波**:VDD_MX / VDDQ 等路径滤波电容
3. **DDR 走线屏蔽**:DDR 信号线周围的包地过孔
4. **主板腔体密封**:前摄 / 传感器 / B2B 连接器处的开孔(结构性泄露点)
5. **WiFi 天线距离**:WiFi 天线与 CPU / DDR 区域的物理距离
6. **中框接地完整性**:中框与主板间的接地,屏蔽罩与中框间的缝隙
7. **点胶工艺**:屏蔽罩点胶量过大可能溢出,导致内部噪声泄露(EMC C.2 案例教训)

**参考案例**:
- [O11-DDR-LLB-aperture.md](../../cases/O11-DDR-LLB-aperture.md) — DDR 从前摄破洞耦合到下天线(LLB 频段,机制参照)
- EMC 2024 C.2 — O11U CPU 屏蔽罩 + 主摄 FPC 噪声叠加(MHB,但屏蔽罩机制一致)

## 三、软件排查步骤

### 步骤 1:场景复现

**目标**:确认 DDR 场景下 WiFi 2.4G Desense 可复现

**操作**:
1. 空载测量 WiFi 2.4G 信道间平坦度 → 基线
2. 启动 DDR 压测 / 下载 / 跑分,使 DDR 达到高带宽
3. 测量压测中 WiFi 2.4G 信道间平坦度
4. 差值 = DDR 场景 Desense

**预期结果**:DDR 压测时 WiFi 2.4G 信道平坦度明显变差,恶化 3-8 dB

### 步骤 2:干扰源确认

**目标**:确认 DDR 为主要干扰源

**操作**:
1. **停止下载 / 减负载**:Desense 是否恢复?
   - 是 → DDR 负载相关
   - 否 → 转 Normal 或 CPU 相关排查
2. **切换 DDR 频率**(DVFS 降频):观察改善
3. **跑 Camera / 下载 / 其他场景**:对比哪种场景最严重
4. **观察时域**:压测瞬间 vs 稳态的 Desense 变化

**预期结果**:确认 DDR 负载与 Desense 正相关

### 步骤 2.5:子功能逐项排查

**目标**:排除同时激活的其他子功能干扰(尤其下载场景会激活 WiFi 本身、USB、屏幕等)

**操作**(按零成本顺序):
1. 关闭屏幕(排除屏 MIPI)
2. 断开 USB(排除 USB 3.0 干扰)
3. 只跑纯内存压测(不跑网络下载)
4. 关闭摄像头(排除 Camera MIPI)

**预期结果**:隔离出 DDR 单独贡献的 Desense 量

### 步骤 2.6:多源叠加排查(若压测 Desense 与 DDR 负载不完全同步)

**触发条件**:步骤 2.5 排除其他功能后仍有残余 Desense,或压测停止后仍有恶化

**操作**:按 [`_template.md` 步骤 2.6](../_template.md) 多源叠加排查法

候选源枚举:
- H1:DDR 时钟 / 数据噪声
- H2:CPU 屏蔽罩泄露(压测时 CPU 也在高负载)
- H3:电源 SSN(DDR 大电流引起的电源突变)
- H4:结构性路径(前摄 / FPC 缝隙,类似 EMC C.1 案例)

### 步骤 3:频率验证

**目标**:验证命中的 DDR 频率 / 谐波

**操作**:
1. 读取当前 DDR 频率(通过系统 log 或命令)
2. 计算该频率的 2-12 次谐波,找出落在 2.4G 内的次数
3. 频谱仪在 2.4G 频段观察谱线,确认特定谐波
4. 改 DDR 频率(DVFS 档位)看干扰频点是否移动

**预期结果**:谐波计算与频谱实测一致,验证是 DDR 时钟谐波命中

### 步骤 4:软件规避尝试

**目标**:软件优先措施

**操作**:
1. **DDR 频率调整**:通过 DVFS 策略避开命中 2.4G 的频率(需系统支持,代价是性能)
2. **DDR Refresh 策略优化**:降低 Refresh 频率可能减轻 EMI(较小改善)
3. **内存访问模式优化**:避免极端突发访问
4. **WiFi 信道避让**:若干扰集中在 ch1/ch6/ch11 某几个,业务层避开(权宜方案)

**预期结果**:软件措施通常改善 1-3 dB,对结构性路径无效

## 四、硬件排查步骤

**触发条件**:软件措施改善不足,或 DDR 频率不可调

### 步骤 1:路径确认

**目标**:判定辐射 vs 传导 vs 结构性路径

**操作**:
1. **近场扫描**:扫描 CPU 屏蔽罩边缘 / DDR 区域 / FPC / 前摄开孔 / B2B 连接器
2. **临时屏蔽测试**:用铜箔临时封住可疑泄露点,看改善
3. **电源纹波测量**:测 DDR VDD 在 2.4G 频段内的纹波
4. **天线拉距测试**:若条件允许,外接天线到远离 DDR 的位置

**预期结果**:定位最强辐射点和主要路径

### 步骤 2:硬件整改验证

**目标**:综合整改

| 整改点 | 措施 | 预期改善 |
|---|---|:---:|
| CPU / DDR 屏蔽罩 | 全方位导电泡棉压紧屏蔽罩与中框 | 3-6 dB |
| 屏蔽罩焊接 | 加强屏蔽罩焊接 / 点胶均匀性 | 2-4 dB |
| DDR 电源滤波 | VDD_MX 加大容值电容 / 串磁珠 | 2-3 dB |
| 结构性路径(前摄 / FPC) | 堵漏:加绝缘胶 / 泡棉 / 金属屏蔽 | 3-8 dB(视路径) |
| WiFi 天线布局 | 天线与 DDR 区域距离增加 / 天线方向优化 | 1-4 dB |
| 中框接地 | 中框镭雕面优化,接地点就近选择 | 2-4 dB |
| 点胶工艺管控 | 减小点胶量,增加 CCD 检测 | 1-3 dB |

**预期结果**:综合改善到内部限值(≤ 4 dB)

- **DVFS**:Dynamic Voltage and Frequency Scaling,动态调频调压
